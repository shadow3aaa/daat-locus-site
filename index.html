01How it works

You ask once.A crew splits the work.

  1. 01

    Just ask

    Talk to Daat Locus the way you would talk to a capable assistant. Simple questions get a direct answer.

  2. 02

    A crew assembles

    For bigger jobs it creates Actors and names each one for its task: Hermes plans the trip, Metis compares the options. Each Actor gets a model chosen for the job, balancing ability and cost.

  3. 03

    Everyone works at once

    Each Actor handles its own part in parallel with the others, on whichever of your devices fits the job.

  4. 04

    Results come back to you

    Progress and results land in the same conversation, in plain language. Open any Actor to see exactly what it is doing.

Daat Locus fully supports MCP. Add any standard MCP server and every Actor on that device can use it.

All Actors on a device share the same tools. That device's permissions decide what they can touch, and the rules are the same for every Actor.

03Safety

Free to work.Fenced in by default.

Actors work inside the sandbox your operating system provides. To go further they have to ask, and you always have the final say.

  1. G1Sandbox

    Safe by default

    On Windows, macOS and Linux, commands and file changes run in the system's own sandbox. If the sandbox isn't available, the command doesn't run at all.

  2. G2Review

    A second look

    When an Actor needs more access, an independent review checks exactly what it is asking for, then approves or declines.

  3. G3Your call

    You have the last word

    If a request is declined, the Actor can take it to Daat Locus. Daat Locus checks it against what you've already allowed and asks you when it isn't sure.

  4. G4No replays

    Nothing runs twice by accident

    Approving a request never quietly re-runs anything. If an action was interrupted and its result is unclear, it is recorded, not repeated.

Administrator access is never automatic. On desktop, an Actor can ask to run one specific command with elevated rights. Each request is reviewed on its own and never turns into blanket permission.

04Devices

Laptop, desktop, phone.One assistant.

The same conversation everywhere

Sign in with the same account on each device and you get the same assistant and the same conversation. If one device goes offline, another takes over automatically.

A private connection

Your devices talk over end-to-end encrypted connections, through a relay you deploy yourself on Cloudflare Workers. There is no server to maintain.

Fine on its own

Only have one computer? Everything works locally, with no extra setup.

Download from GitHub
Build from source

You'll need Rust, Bun and wasm-pack.

shell
git clone https://github.com/shadow3aaa/DaatLocus.git
cd DaatLocus
rustup target add wasm32-unknown-unknown
bun scripts/build-webui.ts
cargo run --locked -- serve
Connect several devices

Deploy the relay to your Cloudflare account once:

shell
cd workers/signaling
bun install --frozen-lockfile
bunx wrangler login
bunx wrangler deploy

Then on each device, turn on relay mode in account settings, enter the same relay address and sign in with the same account.

Notes for Linux

Sandboxed commands need bubblewrap, with user namespaces enabled.
