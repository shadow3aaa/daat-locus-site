01A request in motion

You talk to one Core.
It assembles the rest.

  1. I

    Ask Core

    Core is the one conversation you have. Short questions get a direct answer — no ceremony.

  2. II

    Core names Actors

    For larger work it creates Actors and names each after a fitting mythological figure — Hermes for the trip, Metis for research — choosing a model from your list by capability and cost.

  3. III

    They work in parallel

    Each Actor runs its own serial stream of reasoning and tool calls. Actors advance at the same time, on the device that suits the job.

  4. IV

    Results come home

    Progress and results return to Core, which tells you what matters in plain language. Any Actor’s conversation stays one click away if you want to watch.

Apps are the only tools

An App is a small domain state machine that exposes tools. Files, Terminal, Web, the browser and the virtual screen are all Apps — one abstraction, no special cases.

MCP, unmodified

Any standard MCP server installs as a device App, over stdio or HTTP, with its own connection and request timeouts. No custom protocol to adopt.

Same Apps, same rules

Every Actor on a device gets the same device Apps. What an Actor may touch is decided by the device sandbox, not by per-Actor allowlists.

03Boundaries

Permissions belong to the device,
not to the Actor.

Work runs inside the operating system’s own isolation. When it reaches a real boundary, the request travels a short, auditable path — and nothing is quietly re-run.

  1. Sandbox

    Native isolation, fail-closed

    AppContainer on Windows, Seatbelt on macOS, bubblewrap on Linux. If the platform can’t enforce isolation, the command doesn’t run on the host instead.

  2. Review

    An independent check

    A separate model request, with no tools and no worker history, reviews the exact scope. It can only approve or deny; errors and timeouts deny.

  3. Appeal

    Core asks you

    A denied Actor may appeal to Core. Core checks what you have authorised in the conversation, and asks you when it is missing or unclear.

  4. No replay

    Effects happen once

    A grant never re-executes the original call. After a restart or cancellation, uncertain effects are recorded — not repeated.

Sudo is the one explicit exception on desktop: a single reviewed invocation outside the sandbox, as you or as administrator. Consent never turns into blanket access.

04Devices

One Core,
wherever you are.

Shared, not copied

Your Core’s identity, inbox and conversation are shared by your devices. One device hosts its worker at a time and hands off in a stable order when it goes away.

Encrypted end to end

Devices talk over authenticated, end-to-end encrypted channels carried by a relay you deploy on Cloudflare Workers — no server to maintain. The relay carries traffic; it never owns your work.

Or just one machine

A single device runs the same Actor core locally, with no relay and no extra setup.

05Hands

Agents that can use a computer
without taking yours.

Virtual-screen ComputerUse

Actors operate GUI apps on virtual displays, so they don’t fight you for the mouse. You can watch those displays from the app.

A shared Agent browser

One browser workspace per device. Actors share its tabs and sign-ins, and you can use it as an ordinary browser.

Careful web reading

Plain HTTP without page scripts or ambient cookies, or a rendered page in an isolated WebView.

Terminal & files

Scoped commands and edits, with SHA-256 freshness checks so a stale view never overwrites newer work.

PhoneUse on Android

The APK embeds the service. When you enable it, PhoneUse operates the phone through Shizuku or root.

Bring your history

Import conversations from other AI apps and continue each one as an Actor.
